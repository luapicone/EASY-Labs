1. Ubicación física y la zona: La máquina virtual se encuentra físicamente en un centro de datos de Google. Dado que en los pasos anteriores configuraste la región asia-east1 y la zona asia-east1-b, los servidores físicos que alojan tu máquina están ubicados en Taiwán. La zona que eliges influye en la latencia (al estar en Argentina, notarás un retraso mayor al usarla que si hubieras elegido una región como southamerica-east1 en Brasil), en la redundancia ante posibles fallos de infraestructura y en el precio por hora de los recursos.  
2. Uso de gcloud para la contraseña: Como la máquina virtual acaba de ser creada desde cero, está bloqueada por seguridad y no tienes un usuario inicial. No puedes configurar la contraseña desde el propio Windows porque literalmente estás afuera y la puerta está cerrada con llave. El comando de gcloud le pide a la infraestructura de Google Cloud que se comunique con un agente interno de la máquina para forzar la creación de un usuario (admin) y devolverte una contraseña segura para ese primer ingreso.  
3. Diferencia entre Cloud Shell y el escritorio RDP: Cloud Shell es una pequeña máquina virtual de administración basada en Linux que Google te da temporalmente para que lances comandos de gestión; funciona como el panel de control maestro para organizar tu nube. El RDP (Escritorio Remoto) es la conexión gráfica directa a la máquina Windows Server que tú mismo fabricaste. Usas Cloud Shell para construir la casa desde afuera, y el RDP para entrar a vivir en ella.  
4. Cierre de la ventana RDP: La máquina virtual sigue corriendo en la nube. Cerrar la conexión RDP es exactamente igual a apagar el monitor de tu computadora física: tú dejas de ver la pantalla, pero los procesos, programas y el sistema operativo siguen funcionando con normalidad. Ten en cuenta que, como sigue encendida, sigue generando costos hasta que vayas a la consola de Google Cloud (o uses Cloud Shell) para "Detener" (Stop) o "Borrar" (Delete) la instancia de forma explícita.
